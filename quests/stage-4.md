# Этап 4. Ворота замка

**Навыки:** `git stash`, `git rebase -i` (squash/reword), `git commit --amend`.
**Ветка:** `quest/stage-4-castle`

## Легенда

Прочитай `world/castle/guard.md`. Начальник стражи требует чистую историю.

## Задание

1. Создай ветку `quest/stage-4-castle` от свежего `main`.
2. Впиши в `world/castle/scroll.md` строфу 1 (вместо `___`). Закоммить с сообщением `wip`.
3. Впиши строфу 2. Закоммить с сообщением `ещё wip`.
4. Начни писать строфу 3, но **не коммить**.
5. Вспомни, что стража не примет «wip». Попробуй навести порядок:
   `git rebase -i origin/main` — git откажется, потому что в рабочей копии есть изменения.
6. Спрячь незаконченную работу: `git stash push -m "строфа 3"`.
7. Снова `git rebase -i origin/main`. В редакторе:
   - первый коммит пометь `reword` (или `r`),
   - второй — `fixup` (или `f`).

   Новое сообщение коммита: `feat(castle): дописать заклинание на свитке`.
8. Верни спрятанное: `git stash pop`. Допиши строфу 3.
9. Добавь её в **тот же** коммит: `git add ... && git commit --amend --no-edit`.
10. Проверь: `git log --oneline origin/main..HEAD` — ровно один коммит.
11. `tools/check.sh`, push, PR, merge.

## Подсказки

<details>
<summary>Уже запушил «wip»-коммиты?</summary>

Ничего страшного: после rebase/amend сделай `git push --force-with-lease`. В своей
feature-ветке переписывать историю можно, в `main` — никогда.
</details>

<details>
<summary>Всё сломалось посреди rebase</summary>

`git rebase --abort` вернёт ветку в состояние до начала. А `git reflog` покажет все
состояния HEAD — из него можно восстановить что угодно.
</details>

## Критерии прохождения

- в ветке ровно один коммит с корректным сообщением;
- все три строфы заполнены.
